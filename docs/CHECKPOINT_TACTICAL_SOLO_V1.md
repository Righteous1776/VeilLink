# Tactical Solo V1 — 官渡决战单机版

## 交付范围

原有 7×9《官渡决战》规则、VLGM1 事件和双人重放格式保持不变。本检查点在游戏大厅开放单机入口：玩家固定执曹军先行，袁军由完全离线的 `TacticalBot` 控制。电脑每次只能在 `TacticalState.legalDestinations` 枚举出的命令中选择，选中后还会在状态副本上再次调用 `apply` 校验；策略文件不能创建非法移动、改变骰点或直接修改局面。

首次进入会自动显示六步新手教程。对局右上角的 `?` 可随时打开教程与完整规则，内容包括胜利条件、阶段顺序、全部兵种、地形机动、补给、指挥支援、战斗结算、目标计分和第一轮建议。

## 快速上手

1. 你执曹军。点一支未行动的曹军，再点黄色可达格；攻击敌军时先查看交战预估并确认。
2. 每方每阶段最多两道命令，同一支部队每阶段只能行动一次。第二道命令不合适时可以提前结束阶段。
3. 第一轮优先让步军或骑军向中央官渡推进，让中军随后靠近提供指挥支援；粮队留在主力后方维持补给。
4. 曹、袁双方都行动完才结算目标：乌巢 2 点、白马 1 点、官渡 2 点。站在目标旁边不计分，必须占据目标格。
5. 先到 8 VP、占领敌营或击溃敌方中军即胜。八轮后比较 VP，同分为和局。

## 完整规则摘要

- 中军：攻 3、防 4、机动 2；相邻友军获得 +1 指挥支援。
- 步军：攻 3、防 3、机动 2。骑军：攻 4、防 3、机动 3。
- 远程：攻 2、防 2、机动 2、射程 2。粮队：攻防 1、机动 1、仅 1 步。
- 平原、驿道、渡口、营地消耗 1；林地、丘陵消耗 2；河道不可进入。林地、丘陵、营地给守方 +1。
- 补给从己方大营或存活粮队沿可通行、未被敌军占据的格子连接。断粮后机动力降至 1，战斗值 −1。
- 攻击分为兵种攻击＋d6＋补给＋指挥；防御分另加地形。攻击高 1–2 使守军损失 1 步，高至少 3 损失 2 步；防御反高至少 3 时攻击方损失 1 步。
- 战斗骰由对局编号、命令序号和参战单位确定；离线、重开历史或断线重连均能得到相同结果。

## 本地策略训练与性能边界

`TacticalBotPolicyV1.json` 是 12 特征的线性命令排序器，特征覆盖即时胜负、VP、兵力、目标控制与压力、补给、中军安全、敌中军威胁、大营推进和提前结束阶段。`Tools/AgentTraining/train_tactical_policy.py` 使用 96 组确定性成对评审样本训练 240 轮，可无第三方依赖地复现资源文件。

这是独立策略，不会被加入历史上的 Gomoku/Xiangqi/Ludo 通用 `VLPOL1` 模型。资源很小、没有网络和后台训练，适合 iPhone 7 级设备；真实设备耗时与热表现仍须由物理设备门禁确认，不能用模拟器结果代替。

## 验证要求

- 同一状态、对局编号和策略必须选出同一命令。
- 错误阵营或已结束局面不得产生命令。
- 单机控制器必须自动完成袁军的两道命令并把行动权交还玩家。
- 策略训练脚本输出必须与随包 JSON 完全一致。
- 既有双人兵棋的确定性重放、协议 4、VLGM1 v1 和 SQLite Schema V8 不得变化。
