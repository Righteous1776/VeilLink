# TEST_PLAN — Codex 原生实战训练验收矩阵

## T0 真实性与一致性（0 容忍）

- 固定 Git commit + 源文件哈希，逐局生成真实 Swift `GomokuBot.chooseMove` 决策；预置开局步数单独计数。
- 用产品 `GomokuState.apply` 和**独立实现**（Python 只作裁判）的规则校验：15x15、先黑后白、无重占、胜后禁止加手、五连线四方向、225 手平局。
- 对全部完成局输出可重放 game_id、状态、终局胜方；崩溃/中断/错误/未胜未平不能算 `completedGames`。
- 手动构造畸形序列、假胜利、越界索引、重复占位、把 seed 标签改掉；导入必须拒绝，已存在数据不能被修改。
- 精确报告 91,530 次 Bot 搜索决策与 2,000 个外加首手，不能写成 93,530 次“自主决策”。

## T1 可复现、去重与数据质量

- S0=10、S1=1,000、S2=10,000、S3=50,000 必须分别落地 checkpoint + 原始数据 + hash manifest；可在任意阶段中断。
- 核对完整棋谱精确去重数、对称去重数、局面去重数、开局分层、双方阵法搭配、预算分层、胜负和 draw。旧 2,000 局仅 236 种不同完整序列是警示：禁止依靠重复量报喜。
- 训练 / 评测集不能共享相同棋谱或对称等价局面；特别标识同一首手/同一前 6 手的泄漏。报告每个 held-out 子集的真实数量。
- 所有 JSONL 分片原子落盘；删除最后一个半写入分片后恢复，不重计已成功对局；对损坏 shard fail-closed。

## T2 战术优先级与不降智

- 在所有 6 种阵法模式、训练经验 OFF/ON、各棋力预算下跑强制获胜、阻止对方一手五连、双威胁、活三/冲四、禁非法落子、边缘坐标、重复局面复盘。
- PR #111、#113 已有 forced-block / immediate win guard；必须真实 `XCTest` + Linux Swift tester 双重验证。
- 记录和回归 `GomokuBot.chooseMove` 在风险局面的实际坐标，不以分类标签正确率代替战术正确率。
- 显式风险：旧训练档案把 `guest` 白方当作 AI, `host` 黑方当作 human；Bot-vs-Bot 时这不是“真人经验”。提议**颜色对称**的角色奖励计算，必须兼容原存储逻辑并通过跨颜色实战验证。未经批准不可重写持久化 schema。

## T3 棋力统计（与训练局数分开）

- 至少在独立未见过的开局族跑 5,000 **paired opening blocks**，每对互换执黑/执白且保持同一时间预算与设备条件；若耗时太大，先跑 200/1,000 对并写出不确定性。
- 双层基线：无训练的**同一原生 Bot**；若许可证和运行接口允许，再评估较强的 **PVS/VCF** 引擎。
- 训练侧胜、基线胜、和棋、积分率、Wilson/Bootstrap 95% 置信区间、按开局族分层、左右交换偏差、每手节点和平均耗时。过去 450 局 53.0% 只算探索性迹象。
- **推广门槛**：95% 置信区间下界 >50%（对相同原生基线），零非法对局，零必胜/必防强制回归，时延/温升不突破设备预算；未过时保留策略为实验选项，不覆盖默认。与 PVS 对照另行报告而不偷换基线。
