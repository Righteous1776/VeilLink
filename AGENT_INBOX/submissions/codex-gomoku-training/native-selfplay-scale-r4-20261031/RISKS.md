# RISKS — 实际发生的缺陷与待解决风险

| P | 风险 | 已知依据 / Codex 必须处理 |
|---|---|---|
| P0 | 把棋形分类当“实战” | 14,244 幅合成棋盘图像只有形状标签，不能计入 `GomokuBot` 经验；CNN 分类准确率≠ Elo。 |
| P0 | 2,000 局重复计数为 2,000 新经验 | 仅 236 种完整走法，10,710 种不同局面。必须显示游戏数/去重数/有效战术覆盖。 |
| P0 | 将白胜计 AI 胜、黑胜计“真人胜” | `AdaptiveBoardLearningStore` 现有 `aiWon` 和 `humanWon` 是客/主兼容枚举，**两侧均 Bot 时不存在真人**；奖励设计有白方偏置，必须提案修正。 |
| P0 | 学习偏好凌驾一手必胜/必防 | 强制战术必须第一优先，探索策略不可移走这个防线。来自 PR #111/#113 的修改不能被重复补丁覆盖。 |
| P0 | 训练影响更强的 PVS/VCF 默认 | PR #112 第三方 JS 搜索有独立接口；训练偏好对原生 Bot 有效，不能假称 PVS 已消费此偏好；保持 opt-in。 |
| P0 | 当前数据发布状态误报 | PR #114 仍是 Draft、stacked #113→#112；CI 以**最新头 SHA**为准，旧成功/被取消 run 不代表最新版验收。 |
| P1 | 单包过大导致导入失败 | 当前 `GomokuBundledNativeSeed.verify` 严格 3MB + 最多 10,000 局 + 固定 engineRevision；50k 直接拼单包必失败。 |
| P1 | 每局编码整个 JSON 历史 | 原学习库存储 position 字典、recentGames 全历史；频繁保存将出现 O(n²) 总 IO / RAM 膨胀。不得无授权破坏 schema。 |
| P1 | 统计泄漏/同盘重复 | 开局相同与棋谱 8 对称旋转/镜像，随机 train/test split 容易严重高估。 |
| P1 | 非完全确定搜索 | `GomokuBot` 搜索受 `Date` deadline 限制；同一 seed 可能因负载获得不同搜索深度。报告设备/编译器和预算，独立检查。 |
| P1 | 误报每一手 Bot 自主 | 旧 2000 数据每局 1 手黑先手固定预置；Bot 自主 91,530 手，不能报 93,530 手 Bot 自主。 |
| P1 | 旧训练贡献不均衡 | 现有 on-device `NativeGomokuSelfPlay.play` 中黑方阵法偏好关闭、白方按所选模式，只有 17 个候选首手；与旧 Linux 2000 局 81 起点/双侧 mode 混合不同。 |
| P1 | 不稳定设备状态 | 长时 iOS 自对弈可导致发热、被系统挂起或高耗电；按前台、批次、可中断管理，绝不以 UI 点击次数当落盘数。 |
| P2 | 外部资源许可 | PR #112 vendor 引擎 MIT，但必须保留许可证/PROVENANCE；不得擅引不明许可证权重与不可公开个人棋谱。 |
| P2 | Git/Inbox 污染 | 禁止 ZIP/IPA/可执行二进制/大 JSONL/模型权重或个人日志进 Inbox；研究目录用外部存储和哈希清单。 |

### 已知交叉冲突

- PR #110 Owner 历史对局/八卦阵、PR #111 自对弈与强制防守、PR #112 vendor JS 引擎、PR #113 阵法、PR #114 原生 2000 局训练包。Codex 必须主动核对差异、记录重叠，不把别人的大 PATCH.diff 直接覆盖新版本。
- PR #109 全局文件导入仍有独立待审工作；自对弈内置包依赖 Bundle，但用户侧训练包导入不能因新任务忽略已知系统导入问题。
- Governance `AGENTS.md` + Issue #6；Codex 默认只操作本独立任务 Inbox 子树。
