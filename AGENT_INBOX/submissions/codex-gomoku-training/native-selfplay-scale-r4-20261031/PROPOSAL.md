# PROPOSAL — 让 VeilLink 真正通过原生五子棋对局积累经验

## 核心纠偏（Owner 明确要求）

先前 14,244 幅棋形图和 CNN/ExtraTrees 训练是**棋形识别**，不是 VeilLink `GomokuBot` 的对弈；Python 代用引擎跑出的棋局也不是产品原生实战。只有使用产品原生 Swift `GomokuBot.chooseMove` 和 `GomokuState.apply`、完成合法终局、经独立重放校验的逐局记录，才记为“完成的原生自对弈实战”。最终只有通过完整性校验并**实际持久化导入 App**，才能记入 UI“已学习局数”。

## 当前可核查的实际成果（2026-10-31）

- 使用 `bc919b454379841180fb8698a9e0addec87e7af0` 对应原生 `GomokuBot` / `GomokuState` Swift 源码的 Linux Swift 6.2.1 优化编译执行：**2,000 完整原生 Bot 对局**（注意：执行场所是 Linux，不是 iPhone 设备）。
- 2,000 局共 **93,530 手**：**2,000 个明确预置的黑方首手** + **91,530 次原生 Swift Bot 实际落子决策**。
- **236 种不同的完整棋谱**，**10,710 种不同的落子前局面**；大量重复，不能把 2,000 局写成“2,000 种新经验”。
- 胜负：黑/host 胜 **1,102**；白/guest 胜 **860**；和棋 **38**。
- 81 个不同的首手种子；双方六类阵法模式的 36 种组合，三档搜索预算。独立 Python 五连线、合法走子和终局复盘：2,000 局发现 **0** 局无效。
- 原生 Bot 训练偏好 vs 未启用偏好的探索性**450 局**对照（225 个首手、互换执棋）：有训练侧胜 **217**、基线胜 **190**、和棋 **43**，积分率 **53.0%**。不足以证明稳定棋力增益；首手覆盖与训练数据存在重合，**不能称为严格独立盲测**，也没证明优于第三方 PVS/VCF。

## Codex 的实际任务

第一阶段必须**复现实验**：从 PR #114 对应源码提取纯 Foundation 运行核心，编译原生 Swift，运行小样本、比较完全合法棋局。第二阶段**扩展探索分布、破除重复**，但不能修改用于判定合法走子的 `GomokuState`，不能用 Python/规则机器人代替目标 Bot。第三阶段**批量训练并落盘**：1,000 → 10,000 → 50,000 局，质量足够后再提出 100,000 局的资源计划；遇到退化必须停止策略推广而非停止保存可验证的原始研究数据。第四阶段**独立棋力评测**、以 Draft Inbox 给出可审核的建议与导入方案。

## 核心工程原则

“训练量”和“棋力”分开报告；每一局都有合法走子、可验证赢家、Bot 决策证明、引擎 commit 和参数；研究数据独立于玩家历史和中国象棋数据库；原生训练经验默认**不能绕过先手必胜/必防**，也不能默认取代可能更强的 PVS/VCF。训练代理不能只交宏大计划，要交**实际执行统计、脚本、失败样例和可验证报告**。
