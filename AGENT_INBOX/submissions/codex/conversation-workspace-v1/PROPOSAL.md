# PROPOSAL — 会话工作台

## 产品目标

VeilLink 已有搜索、引用回复、图片/语音、置顶和本地删除，但长对话仍只能从头翻找。会话工作台把聊天从“消息流”提升为可使用的本地信息空间：一次整理完整历史，按行动、问题、链接和附件查看，并能跳回原消息继续上下文。

## 功能

1. **会话概览**：消息总数、收发数量、活跃天数、行动项、问题和资料数量。
2. **行动项**：识别 `待办`、`记得`、`别忘`、`请`、`需要`、`安排`、`TODO`、`[ ]` 等明确前缀。
3. **待回答问题**：识别中英文问号和常见中文疑问开头。
4. **链接资料库**：从正文与新回复中提取 HTTP(S) 链接，清除尾随标点；长按可复制到仅限本机、5 分钟过期的剪贴板。
5. **附件索引**：图片、语音和其他附件显示类型、大小及收发方向。
6. **组合筛选**：类别与关键字同时过滤。
7. **回到原消息**：条目点击后关闭工作台，并由现有 `ScrollViewReader` 跳转到对应气泡。
8. **后台全历史分析**：打开工作台时在后台读取完整本地历史，不受正常聊天窗口分页限制；新消息到达时更新工作台。

## 隐私与兼容

- 正文只在本机内存中分析；关闭工作台后不持久化分析结果。
- 不上传、不同步、不调用互联网 AI。
- 不新增数据库表、消息字段或 wire packet；对方无需升级。
- 游戏和兵棋协议消息在进入统计前过滤，避免内部控制包污染结果。
- 引用回复只分析新回复，不把被引用的旧内容重复当成行动项。
- 诊断只记录数量，不记录正文、链接或附件内容。

## 性能

- 数据库完整历史读取、分类和链接识别均在后台队列执行。
- UI 只接收结构化快照，列表按需渲染。
- 使用现有 `messageReloadGeneration` 丢弃过期加载；被其他刷新抢占时恢复 loading 状态，避免按钮永久卡住。
- 正常聊天仍保持设备分级的窗口分页，不因工作台永久扩大渲染负担。

## 验收标准

- 工作台能正确分类中英文行动项、问题、链接、图片和语音；
- 游戏协议包不出现在计数和条目中；
- 点击条目能回到完整历史中的原消息；
- 新消息到达时工作台可刷新；
- iPhone 7 上分析 10,000 条短消息不阻塞主线程；
- 不产生新的明文持久化和网络请求。
