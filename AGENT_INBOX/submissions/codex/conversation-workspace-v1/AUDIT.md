# PRODUCT FUNCTION AUDIT — 2026-10-24

## 已具备且不应重复建设

- 聊天：端到端加密文字、图片、语音、引用回复、搜索、置顶、未读、本地删除、小游戏邀请、灵核助手。
- 连接：BLE、同局域网高速通道、Mesh、双区互联网 Relay、断点附件传输。
- 本地能力：工具中心、实时传感器工具、文件完整性提案、存储管理提案。
- 娱乐：兵棋、棋类、实时 2D/3D 游戏与本地 Bot。
- 治理：A9/A10、深度遥测、MetricKit、压力测试、后台连续性。

## 当前高价值缺口

1. **聊天信息组织**：长对话没有行动/问题/链接/附件视图。由本提交的会话工作台补齐。
2. **发送前编排与安全**：没有协议字节预算、结构模板、敏感内容检查和安全回填。由本次 Message Forge 修订补齐。
3. **聊天清理可达性**：安全清空底层已存在但入口埋在聊天页菜单；revision 3 增加列表右滑与长按入口，并保留强制确认。
4. **任意文件传输**：底层附件协议当前只允许 image/voice 类型，扩展需要正式协议兼容决策，不能在 Inbox lane 偷改。
5. **群聊、reaction、编辑/撤回、已读回执**：均需要 wire/schema/隐私语义设计，应由独立版本化协议提案处理。
6. **跨功能全局搜索/命令面板**：价值较高，但需协调四套 Root 主题与 PR #51 生命周期入口，建议下一批统一设计。
7. **可恢复加密草稿/定时发送**：需要新的加密持久化模型和失败语义，不应使用 UserDefaults 保存明文。
8. **Peer 视频通话/屏幕协作**：需要实时媒体协议、权限和高成本后台策略；当前 Agent Video Chat 不是点对点视频。

## 本轮取舍

优先 Message Forge，因为它无需协议/schema 变化即可立即改善每次发送：模板化、可读性、16 KB 限制预警、敏感信息阻断和手动回填。它与会话工作台组合后形成“整理历史 → 形成草稿 → 安全发送”的完整本地闭环。
