# PROPOSAL — Feature Century Program

## 结果定义

用户目标是增加 100 项极其强大且实用的功能。本提交先解决规模化交付最容易失败的地方：重复计数、半成品入口、协议互斥、P0 触控回归和“候选即上线”的虚假状态。

`VEILLINK_FEATURE_CENTURY_V1.md` 给全部 100 项分配稳定 ID、领域、当前状态和可证伪的完成门槛。FC-001–020 对应已经存在的 Mission Control 候选，但 PR #67/#68 API 冲突，只能选择一个实现；FC-021–100 是去重后的新增能力。

## 强制质量规则

1. 不按按钮数量计功能；一个功能必须能完成明确用户任务。
2. 不把模拟样本称为实时设备能力。
3. 不把 Inbox/Draft/CI 计划称为已上线。
4. 每项都有空输入、超限、权限拒绝、取消、失败和恢复语义。
5. 触及 wire/schema/Keychain/签名/extension 的项目必须进入独立受保护批次。
6. iPhone 7 默认性能预算必须存在；上帝模式覆盖必须显式并可恢复。
7. 所有 AI 能力显示模型、输入范围、联网状态和来源证据。
8. 所有删除/覆盖/发送动作必须有确认与可理解的影响范围。
9. 每波最多 10 项，避免无法定位回归的大爆炸合并。
10. P0 #64–#66 未裁决前，不新增全局手势或依赖不稳定触控的发布声明。

## 本轮为什么不提交 100 份 Swift 实现

Build 61 当前正在处理真实 iOS 15 触控、Keychain/SQLite 连续性事故；同时已有两套互相冲突的 20 功能实现。此时批量生成 100 份 UI 会扩大事故面，且无法在当前无 Xcode 的环境验证。规划包把下一步收敛为可审查波次，随后逐波提交真实源码与测试。

## 下一实施波

在 P0 门完成后，先由 Governor 选择 PR #67 或重命名后的 #68 作为 FC-001–020 唯一实现。随后优先 FC-041–060：安全号码、附件隔离、元数据清洗、备份健康、全局命令面板、本地工作流、加密收集箱、Diff/Merge、跨时区规划和通用导入预检。
