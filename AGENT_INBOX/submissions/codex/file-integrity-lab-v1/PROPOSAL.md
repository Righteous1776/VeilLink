# PROPOSAL — 文件完整性工具

## 产品目标

VeilLink 已经能发送图片、文件并提供 BLE/LAN 链路能力，但用户在“发送前、接收后、备份后”缺少一个简单可信的本地核验入口。现有“文本指纹”只能处理粘贴文字，不适合大文件，也不能直接比较两份文件。

本提案在工具中心增加“文件完整性”：

1. 从系统文件选择器读取任意普通文件；
2. 用 512 KiB 固定块流式计算 SHA-256，不把整个文件载入内存；
3. 显示文件名、实际读取字节数和完整 SHA-256；
4. 可选第二份文件，依据字节数与 SHA-256 给出“一致 / 不一致”结论；
5. 生成不含绝对路径的本地校验报告，并使用 5 分钟自动过期、仅限本机的剪贴板；
6. 页面退出时取消仍在进行的读取。

## 实现结构

- `VeilFileIntegrityEngine.swift`
  - Foundation/CryptoKit 只读引擎；
  - 安全作用域 URL 生命周期在引擎内部成对管理；
  - 每个块检查 Task cancellation；
  - 以实际读取总量计数，避免仅信任文件元数据；
  - 把底层路径/系统读取错误收敛成稳定的本地化错误，不把路径写入 UI 或报告。
- `VeilFileIntegrityToolView.swift`
  - 两个清晰的文件槽位；
  - 后台 `Task.detached` 做哈希，主线程只更新 UI；
  - 对比结果、错误态、清除/替换、报告复制都有明确反馈；
  - 使用现有 VeilTheme、VeilMotionPolicy 与工具按钮样式，支持 Reduce Motion。
- `ToolCenterView.swift`
  - 在“文本指纹”之后增加入口和中英文搜索词。
- `VeilFileIntegrityEngineTests.swift`
  - 固定 SHA-256、空文件、跨分块大文件、相同/不同对比、报告隐私和目录拒绝。

## 边界

这是纯本地只读工具，不接入消息协议，不自动读取聊天附件，不扫描目录，不上传文件，不做端口/网络探测，也不持久化文件 URL。它不会改变 Protocol 4、SQLite V8、BLE/LAN 数据面或密钥合同。

## 验收标准

- 选择 0 字节、小文件和大于一个读取块的文件均能得到正确结果；
- 两份相同内容但不同文件名的文件判定一致；
- 同尺寸不同内容判定不一致；
- UI 操作期间无主线程整文件读取；
- 报告不含绝对路径；
- iOS 15 Simulator build 与全量 XCTest 通过。
