# Kimi · Veilopoly 统一规则动画与视觉待办（只做视觉，不改引擎）

## 本轮新增 7 种语义 Effect

| EffectKind | 触发 | 需要 Kimi 提供的动画方案与资源 |
|---|---|---|
| `bankDeposited` | 活期/定期资金转入银行 | 钱币到银行抽屉的过渡，金额数字从玩家 HUD 移动，支持隐藏金额模式 |
| `bankWithdrawn` | 存款解锁与取回 | 银行资金回到玩家筹码，破产清算本金返回时使用低饱和版 |
| `bankBorrowed` | 借款放款、期数/总额告示 | 借款契约展开、利息与到期标签、抵押资格说明 |
| `bankRepaid` | 贷款偿还 | 筹码流向银行，契约盖章已结清，不用现实信用分数或真实金融品牌 |
| `bankInvestmentOpened` | 规则表已批准才可开仓 | 虚拟市场/理财卡片入库、单一资金去向动画 |
| `bankInvestmentSettled` | 期满后由引擎给出 1–6 骰面、收益 | **只动画化 Effect 给出的骰面和整数结果**，不得重新抽随机数 |
| `bankMatured` | 期限达到 | 银行图标轻震和红点、无自动扣费/转账动画 |

## P4 横屏布局与交接边界

- 真横屏全屏，iPhone 844×390pt / 852×393pt；iPad 约 1180×820pt；40 格棋盘完整可见。
- 右上双键胶囊 `•••` 更多 / 圆圈退出不可被经济动画遮挡，必须保留每键 44pt 的触控热区。
- 当前 SwiftUI 只有功能性银行操作面板：金额、贷款期数、活期存入、申请贷款、回收存款、偿还贷款、到期投资结算；Kimi 按现有功能布局做最终美术，不要自行新增不会执行的按钮。
- 没有已裁决收益表时，定存/理财/股票/风险投资的 UI 必须显示未开放或待规则确认，不可虚构收益数字、收益率和结算。
- SpriteKit 动画执行 ViewCommand 队列，完成必需 ACK 一次且仅一次。资源都标注具体源 URL、版权、alias、尺寸、锚点、图集帧、8 层 zPosition 和内存预算。
