## 按证据修复的故障

1. **行情非原子更新**：原先 `StockMarketEngine.advance` 原地推进 tick/RNG/报价，末尾验证失败会使直接调用者拿到半更新的数据。现在采用 **copy → advanceChecked → validation → commit**。有效 tick 的随机数消耗与价格结果不变，V1/V2 原轨迹均保持。
2. **贷款可无视到期**：V2 新建银行账本按 `completedTurns` 自动偿还现金足够的已到期贷款，按到期先后再按合同 ID 排序；现金不足不制造负数或擅自抵押。真正逾期时拒绝继续新增借款、存款、投资和买入股票，合法偿还、取款或卖出模拟股票仍可执行。没有未批准的滞纳金和随机利息。
3. **旧存档不受新还款规则强制改变**：`IntegratedBankLedger.financeRuleVersion`，历史 JSON 缺失字段时按 V1 恢复，V1 编码省略新键，保留旧封存校验字节；新账本 V2 才执行自动到期规则。股票 V1/V2 版本机制仍独立。
4. **破产资产无声丢失**：原 `closeBankruptAccount` 可能因为现金上限而跳过某笔本金/证券估值，却仍然清空账户。现在**所有资产先预检查**，超限则安全拒绝本次清算，不修改这次失败的游戏状态；普通可结算情况下继续沿用现有清算金额/优先级。超上限清算的根本清偿办法仍需要单独设计，不能假装已自动解决。
5. **重复合同 ID 漏洞**：银行校验现拒绝同一玩家账户内重复的存款/贷款/投资 ID，防止「扣一笔贷款却删掉同 ID 两笔记录」。
6. **可通过等待重掷投资收益**：新银行 V2 的投资结算骰数由对局 seed + 真实投资合同 ID 的**独立域隔离 RNG**决定；不随声明结算的迟早、其他骰子消耗、股票 Tick 改变。V1 保留原共享 RNG 行为，避免旧存档重放分歧。**此项不启用未批准的收益表，也不增加下注功能。**
7. **界面过期提示**：银号到期巡检改为显示实际逾期期数，地契/银行账单标明贷款 V1/V2，错误码 `financeOverdue` 可解释新增订单为何被阻止；旧规则说明已同步。

## 平衡抽样（独立模型，对当前 V2 算法的复刻，非 Xcode Swift 实机）

在 Python 中按 `StockMarket.advance` 的参数、SplitMix64 计数器、整型截断规则进行等价算法抽样：
- **128** 个独立种子，每局 **240 Tick**，每局 5 家公司；
- 总计 **73,304 次上涨** 与 **73,009 次下跌**（另有不变 Tick）；
- 5 家公司在240 Tick 末的收益中位数依次约 **-1.32% / -0.34% / -0.59% / -0.94% / -0.76%**；
- 所有样本单一股票收益的 5%–95% 分位区间约 **-10.56% 至 +9.76%**；
- 市场状态切换中位数 **8** 次，最少1、最多16；说明没有固定每24 Tick 切换的机械节奏。

**解释**：从本批短期抽样不能证明游戏已达到公平平衡，但没有出现只涨不跌、只有单一结局的简单异常。短期内不继续未经批准地抬高或降低股价波动率。对应新增 Swift 多种子统计测试覆盖两侧走势、多样性、停牌次数和每日限价。

## 仍然需要 Owner 裁决或实测的事项

- 银行原始照片中的定期存款利率、各类投资六档回报表、贷款抵押顺序、破产债权分配尚未正式敲定。仅对已实际签订的模拟合同执行已存的 `totalDue`，不自行创造收益率。
- 破产现金上限之外的超大资产，现阶段保护数据而拒绝危险清算；需要后续由制度 Owner 设计合法的分批清算/托管。
- 旧银行 V1 仍使用先前自愿还款规则；旧股票 V1 使用旧行情算法，未偷改正在进行的历史对局。
- 实时 Tick 由 UI 在活跃前台以约2秒间隔请求；iOS 调度/后台暂停可能导致不同时间里的 Tick 数量不同，但相同已提交操作序列可确定性重放。
- 赌博样式仅限**无真钱、无提现、无奖品兑换**的桌游随机性；不新增下注或取款游戏模块。
